Heritage Site Information System

A Django platform designed to manage heritage-site information while keeping transactional work and analytical reporting workloads distinct.

DJANGO APPSERVICE LAYERPOSTGRESQLMONGODB

Problem

Heritage-site information needs operational records and reporting support, with different data-access patterns for each.

Solution

A Django application with a service layer and a dual-database design: PostgreSQL for transactional data and MongoDB for analytical and reporting workloads.

Architecture

The interface connects to Django and its service layer, which keeps application logic separate from the transactional and analytical data stores.

Key decisions

Separate workloads

PostgreSQL supports transactional records while MongoDB supports analytical and reporting needs.

Repeatable delivery

Docker and GitHub Actions make the application workflow repeatable.

Outcome

45 testsSUPPORTED BY TWO DATABASE ENGINES AND A CI/CD PIPELINE
